You are a senior full-stack engineer, computer-vision engineer, ML engineer, product designer and hackathon technical lead.

Build a complete working MVP called “GrainGuard”, an AI-powered smartphone-based grain quality inspection and digital certification system for rural grain procurement centers.

The objective is NOT to build an industrial grain sorting machine or replace laboratory/NIR testing. The objective is to demonstrate that visible grain-quality inspection can be made more objective, measurable, explainable and auditable using a smartphone camera, a standardized low-cost tray and computer vision.

IMPORTANT:
Prioritize a WORKING END-TO-END MVP over unnecessary complexity.
The system must be easy for a student hackathon team to run locally.
Do not build unnecessary blockchain, payment, IoT, marketplace, complicated authentication, or microservice infrastructure.
The primary validated MVP grain type is RICE/PADDY. Design the code so wheat and pulses can be added later through separate models/configurations.

==================================================

1. PRODUCT CONCEPT
   ==================================================

User workflow:

1. Procurement agent opens GrainGuard.
2. Creates a new inspection.
3. Selects grain type = Rice.
4. Enters optional farmer/batch reference.
5. Places a representative grain sample on a standardized contrasting tray.
6. Captures a top-down smartphone photograph.
7. Frontend sends the image to the backend.
8. Backend validates/preprocesses the image.
9. Computer vision model detects/classifies visible grain objects.
10. System identifies:

* whole grain
* broken grain
* discolored/damaged grain
* insect-damaged grain
* foreign matter

11. Quality engine calculates percentages.
12. System produces a transparent quality score.
13. Results are displayed with annotated image evidence.
14. Inspection is saved.
15. A digital certificate is generated with a unique ID and QR verification code.
16. QR opens a public verification page showing the inspection result.

Target processing time for the prototype should be approximately 30 seconds or less, but never fake or hardcode processing performance. Measure and display actual processing time.

4. IMAGE PROCESSING
===================

Implement an image preprocessing pipeline:

1. Load image.
2. Validate image.
3. Detect/crop inspection area where possible.
4. Normalize image.
5. Resize appropriately.
6. Run AI inference.
7. Generate annotated output image.
8. Return structured detection data.

Add image-quality checks where practical:

* image too dark
* image too blurry
* insufficient detectable objects

If quality is clearly insufficient, return a warning requesting recapture rather than pretending the AI result is reliable.

Do not overengineer automatic tray detection for the MVP.

The frontend should guide the operator to place the grains inside a visible tray boundary.
